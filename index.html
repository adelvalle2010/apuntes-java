Introducción a Java

1¿Qué es Java?

Java es un lenguaje de programación de alto nivel, basado en clases y orientado a objetos. Lo diseñó Sun Microsystems, que hoy es propiedad de Oracle.

Es independiente de la plataforma, seguro y robusto. Se usa muchísimo para crear aplicaciones empresariales, apps de Android, aplicaciones web y más.

2Características de Java

  • Simple
  • Orientado a objetos (POO)
  • Independiente de la plataforma
  • Seguro
  • Robusto
  • Multihilo (multithreaded)
  • Neutral respecto de la arquitectura
  • Portable
  • Alto rendimiento
  • Distribuido
  • Dinámico
  • Gestión automática de la memoria (recolector de basura, GC)

3JDK, JRE y JVM

Son tres piezas que van una adentro de la otra. Fijate en el dibujo: la más grande contiene a las otras dos.

  • JDK (Java Development Kit, kit de desarrollo de Java): brinda las herramientas para desarrollar, como javac, java, el depurador (debugger), etc.
  • JRE (Java Runtime Environment, entorno de ejecución de Java): brinda las bibliotecas, la JVM y otros componentes para ejecutar programas Java.
  • JVM (Java Virtual Machine, máquina virtual de Java): ejecuta el bytecode y brinda el entorno de ejecución.
Qué contiene cada componente
ComponenteContiene
JDKJRE + JVM + herramientas de desarrollo (javac, jar, javadoc, etc.)
JREJVM + bibliotecas principales (core libraries) + otros componentes de ejecución
JVMCargador de clases (Class Loader) + verificador de bytecode + motor de ejecución (Execution Engine) + áreas de datos de ejecución (Runtime Data Areas)

4¿Cómo funciona Java?

El código Java (.java) se compila a bytecode (.class) con el compilador de Java (javac). Después, ese bytecode lo ejecuta la JVM en cualquier plataforma.

5Flujo de compilación y ejecución

Recorrelo paso a paso con los botones, o dejá que avance solo.

6Tu primer programa en Java

// Programa Hola Mundo
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("¡Hola, Java!");
    }
}
  • La palabra clave class → define una clase.
  • main() → es el punto de entrada del programa.
  • System.out.println() → imprime la salida.
  • Cada sentencia termina con ;
  • El nombre del archivo tiene que coincidir con el de la clase (HelloWorld.java).
Recordá
  • Java es «Write Once, Run Anywhere» (WORA): escribilo una vez, ejecutalo en cualquier lado.
  • La JVM hace que Java sea independiente de la plataforma.
  • El bytecode es el corazón de Java.
Dato para la entrevista

Java lo diseñó James Gosling en 1995 y se lanzó por primera vez en 1996. La extensión del código fuente es .java y la del bytecode es .class.

Error común
  • Que no coincidan el nombre del archivo y el de la clase.
  • Olvidarse del método main().
  • No entender la diferencia entre compilar y ejecutar.

JDK, JRE y JVM

1 · JDK (Java Development Kit)

  • Es el paquete completo para desarrollar en Java.
  • Incluye el JRE + herramientas de desarrollo.
  • Se usa para escribir, compilar y ejecutar programas Java.

Incluye: el JRE, el compilador (javac) y herramientas (javadoc, jar, jdb, etc.).

2 · JRE (Java Runtime Environment)

  • Brinda las bibliotecas, la JVM y otros componentes para ejecutar aplicaciones Java.
  • No incluye herramientas de desarrollo.

Incluye: la JVM y las bibliotecas principales (rt.jar, etc.).

3 · JVM (Java Virtual Machine)

  • Es el corazón de Java.
  • Ejecuta el bytecode de Java.
  • Es independiente de la plataforma: Write Once, Run Anywhere.
  • Gestiona la memoria, los hilos (threads), la seguridad y más.

4Proceso de compilación

5Bytecode

  • Es la salida del compilador de Java (javac).
  • Es independiente de la plataforma.
  • Lo ejecuta la JVM, no el sistema operativo directamente.
  • Extensión del archivo: .class.
Nota importante

La JVM convierte el bytecode en código máquina mientras el programa se ejecuta, usando el compilador JIT (Just-In-Time, «justo a tiempo»). Así logra mejor rendimiento.

6Diagrama del flujo de ejecución

  1. Escribir el código Java (.java)
  2. Compilar con javac
  3. Generar el bytecode (.class)
  4. La JVM carga y verifica el bytecode
  5. La JVM ejecuta el bytecode (interpretación + JIT)
  6. Salida en la consola

Java es independiente de la plataforma porque hay una JVM para todos los sistemas operativos principales.

Para llevarte
  • Desarrollás con el JDK.
  • Ejecutás con el JRE.
  • La ejecución ocurre dentro de la JVM.
  • Write Once, Run Anywhere.

Variables y tipos de datos

1¿Qué es una variable?

Una variable es un lugar con nombre en la memoria. Se usa para guardar datos que pueden cambiar mientras el programa se ejecuta.

2Tipos de datos

a) Tipos primitivos: guardan un solo valor

TipoTamañoValor por defecto
byte1 byte0
short2 bytes0
int4 bytes0
long8 bytes0L
float4 bytes0.0f
double8 bytes0.0d
char2 bytes'\u0000'
boolean1 bitfalse

b) Tipos no primitivos: guardan una referencia a objetos

  • String
  • Array (arreglo)
  • Class (clase)
  • Interface (interfaz)
  • Object (objeto)
  • Collection (List, Set, Map)
  • etc.

3Literales

Un literal es un valor escrito directamente en el código.

LiteralEjemplos
Entero25, -10, 0
De punto flotante3.14, -0.5f
De carácter'A', 'z', '\n'
De cadena (String)"Hola Java"
Booleanotrue, false

4Reglas para nombrar variables

  • Tiene que empezar con una letra, $ o _.
  • Puede tener letras, dígitos, _ y $.
  • Distingue mayúsculas y minúsculas (case sensitive): age y Age son variables distintas.
  • No puede ser una palabra clave de Java (int, class, etc.).
  • Ejemplos de nombres inválidos: 1age, int, @age.

5Conceptos básicos de memoria

Nota
  • Cada variable ocupa memoria según su tipo de dato.
  • Los tipos primitivos guardan el valor real.
  • Los tipos no primitivos guardan una referencia (dirección) a objetos en la memoria.
Tip para la entrevista 
int a = 10;
int b = a;     // b recibe una copia del valor
a = 20;        // b no cambia
System.out.println(b); // Salida: 10
Buenas prácticas
  • Usá nombres de variables con significado.
  • Declará las variables cerca de donde las usás.
  • Preferí final para las constantes.
  • Seguí la convención camelCase.

6Conversión de tipos (type casting)

Es convertir un tipo de dato en otro. Hay dos formas:

  • Implícita (ensanchamiento, widening): Java la hace automáticamente, de un tipo más chico a uno más grande.
  • Explícita (estrechamiento, narrowing): la hacés vos a mano, de un tipo más grande a uno más chico.

Implícita (ensanchamiento)

int a = 10;
double b = a;   // int a double

Explícita (estrechamiento)

double x = 25.75;
int y = (int) x;   // double a int
Tip para la entrevista

Los operadores son los bloques con los que se arman las expresiones y las condiciones en Java. Entendé la precedencia y la conversión de tipos para evitar errores (bugs).

Error común

Tené cuidado al convertir tipos: las conversiones de estrechamiento pueden hacerte perder datos. En el ejemplo, y queda en 25 y se pierde el .75.

Sentencias de control

Las sentencias de control cambian el flujo de ejecución según condiciones, o repiten la ejecución de un bloque de código.

1if

int age = 18;
if (age >= 18) {
    System.out.println("Puede votar");
}

✓ Ejecuta el bloque si la condición es verdadera.

2if-else

int n = -5;
if (n >= 0) {
    System.out.println("Positivo");
} else {
    System.out.println("Negativo");
}

✓ Ejecuta uno de dos bloques, según la condición.

3switch

int day = 2;
switch (day) {
    case 1 -> System.out.println("Lun");
    case 2 -> System.out.println("Mar");
    case 3 -> System.out.println("Mié");
    default -> System.out.println("Inválido");
}

✓ Se usa cuando hay varios valores posibles para comparar.

Nota

En Java 17+, switch admite la sintaxis con flecha (->) y también funciona con String y enum. [revisar] La flecha es estándar desde Java 14 y el switch con String existe desde Java 7.

4for

for (int i = 1; i <= 5; i++) {
    System.out.println(i);
}

✓ Es el mejor cuando sabés cuántas veces se va a repetir (cantidad de iteraciones).

5while

int i = 1;
while (i <= 5) {
    System.out.println(i);
    i++;
}

✓ Ejecuta el bloque mientras la condición sea verdadera.

6do-while

int i = 1;
do {
    System.out.println(i);
    i++;
} while (i <= 5);

✓ Ejecuta el bloque al menos una vez y después evalúa la condición.

7break y continue

break

Termina el bucle o el switch de inmediato.

for (int i = 1; i <= 5; i++) {
    if (i == 3) break;
    System.out.print(i + " ");
}
Salida: 1 2

continue

Saltea la iteración actual y pasa a la siguiente.

for (int i = 1; i <= 5; i++) {
    if (i == 3) continue;
    System.out.print(i + " ");
}
Salida: 1 2 4 5
Tip para la entrevista

Elegí la sentencia de control adecuada para que el código se lea mejor y rinda más.

Buena práctica

Evitá anidar demasiado. Usá un return temprano, break o continue para simplificar la lógica.

Métodos en Java

Un método es un bloque de código que hace una tarea específica.

1Sintaxis de un método

2Parámetros

  • Los parámetros se usan para pasarle datos a un método.
  • Funcionan como marcadores de posición (placeholders).
public int add(int a, int b) {
    return a + b;
}
a y b son parámetros.

3Tipos de retorno

Un método puede devolverle un valor a quien lo llamó, usando la sentencia return.

Tipo de retornoSignificado
voidNo devuelve ningún valor
int, double, etc.Devuelve un valor numérico
StringDevuelve un texto
booleanDevuelve true o false

Ejemplo

public int square(int n) {
    return n * n;
}

4Sobrecarga de métodos (overloading)

  • Mismo nombre de método, con distintos parámetros.
  • Hace que el código se lea mejor.
int add(int a, int b) {
    return a + b;
}
int add(int a, int b, int c) {
    return a + b + c;
}

5Recursión

  • Es un método que se llama a sí mismo.
  • Se usa para resolver problemas complejos de una forma simple.
int factorial(int n) {
    if (n == 0) return 1;
    return n * factorial(n - 1); // Llamada recursiva
}

6Alcance de las variables (scope)

TipoAlcanceDuraciónEjemplo
Variable localDentro del método o del bloqueSe crea cuando se llama al método o bloqueint x = 10;
Variable de instancia (no static)Dentro de la clase, fuera de los métodosExiste mientras exista el objetoint age;
Variable static (de clase)Toda la claseExiste hasta que termina el programastatic int count;

7Ejemplo completo de un método

public class Demo {
    public static int multiply(int a, int b) {
        return a * b;
    }

    public static void main(String[] args) {
        int result = multiply(5, 4); // llamada al método
        System.out.println("Resultado: " + result);
    }
}
Tip para la entrevista

Los métodos ayudan a reutilizar el código, a mantenerlo y a programar de forma modular.

Buenas prácticas
  • Usá nombres de métodos con significado.
  • Mantené los métodos cortos y enfocados.
  • Evitá el código duplicado.
  • Seguí el principio de responsabilidad única.
Recordá

Un buen método hace que tu código sea limpio y fácil de entender.

Arrays en Java

Un array (arreglo) es una colección de datos del mismo tipo, guardados en posiciones de memoria contiguas.

1Arrays de una dimensión (1D)

  • Guardan elementos del mismo tipo en una sola fila.
  • El índice empieza en 0.
int[] numbers = new int[5];
numbers[0] = 10;
numbers[1] = 20;
numbers[2] = 30;
numbers[3] = 40;
numbers[4] = 50;

2Arrays de dos dimensiones (2D)

  • Es un array de arrays (filas y columnas).
  • Sirve para tablas, matrices y grillas.
int[][] matrix = new int[2][3];
matrix[0][0] = 1;  matrix[0][1] = 2;  matrix[0][2] = 3;
matrix[1][0] = 4;  matrix[1][1] = 5;  matrix[1][2] = 6;
[revisar] En la lámina decía int[][[] matrix; se corrigió a int[][] matrix porque si no, no compila.

  • Es una forma simplificada de recorrer arrays.
  • El acceso es de solo lectura (no podés modificar el índice).
int[] arr = {10, 20, 30, 40, 50};
for (int num : arr) {
    System.out.println(num);
}

Tip para la entrevista
  • Los arrays tienen tamaño fijo.
  • Si usás un índice inválido, ocurre IndexOutOfBoundsException.
  • Usá for-each para los recorridos simples.
Buenas prácticas
  • Usá nombres con significado.
  • Verificá siempre el índice antes de acceder.
  • Preferí los métodos de la clase Arrays para las operaciones.
  • Evitá guardar muchos datos en la pila (stack): usá arrays en el heap (con new).

Strings en Java

1String

  • Un String es una secuencia de caracteres.
  • En Java, un String es un objeto de la clase java.lang.String.
  • Los Strings se usan muchísimo para guardar y manipular texto.
String name = "Java";
String msg = new String("Hola");
System.out.println(name);   // Java
System.out.println(msg);    // Hola

2String Pool

  • Los literales String se guardan en el String Pool (un depósito de cadenas).
  • Si un literal ya existe, se devuelve la misma referencia.
  • Ayuda a ahorrar memoria.

3Strings inmutables

  • Los objetos String son inmutables: no se pueden cambiar.
  • Cualquier operación que parezca modificarlos, en realidad crea un objeto nuevo.
String s1 = "Hola";
String s2 = s1.concat(" Mundo");
System.out.println(s1);   // Hola
System.out.println(s2);   // Hola Mundo
s1 no cambia. Se crea un objeto nuevo para s2.

4StringBuilder

  • Es una clase mutable que se usa para modificar cadenas.
  • No está sincronizada → no es segura para hilos (not thread-safe).
  • Es más eficiente que String en programas de un solo hilo.
StringBuilder sb = new StringBuilder("Java");
sb.append(" Programming");
sb.insert(5, " is");
sb.delete(0, 1);           // borra la 'J'
System.out.println(sb);    // ava  isProgramming
[revisar] La lámina dice que la salida es ava is Programming, pero con insert(5, " is") sale ava isProgramming. Para que dé lo que dice la lámina, el código tendría que ser sb.insert(4, " is");.

5StringBuffer

  • Es una clase mutable, como StringBuilder.
  • Está sincronizada → es segura para hilos (thread-safe).
  • Es más lenta que StringBuilder, pero segura cuando hay varios hilos.
StringBuffer sb = new StringBuffer("Java");
sb.append(" Programming");
sb.reverse();
System.out.println(sb);    // gnimmargorP avaJ

Clases y objetos en Java

Java es un lenguaje orientado a objetos. Todo en Java es un objeto.

¡Ojo!

Hay una excepción: los tipos primitivos (int, double, boolean…) no son objetos. Guardan el valor directamente, como viste en la lámina 3.

1Clase

  • Una clase es un plano o una plantilla (blueprint).
  • Define las propiedades (atributos, en inglés fields) y los comportamientos (métodos) de los objetos.
  • No ocupa memoria.

Ejemplo: definición de una clase

class Student {
    String name;          // atributo
    int age;              // atributo

    void display() {      // método
        System.out.println(name + " tiene " + age);
    }
}

2Objeto

  • Un objeto es una entidad del mundo real.
  • Es una instancia de una clase.
  • Ocupa memoria en el heap.

Por ejemplo, s1 (con name = "Alice" y age = 20) y s2 (con name = "Bob" y age = 22) son dos objetos de la clase Student.

3 · Atributos (variables)

  • Representan el estado o los datos de un objeto.
  • Cada objeto tiene su propia copia de los atributos.

4 · Métodos

  • Representan el comportamiento de un objeto.
  • Trabajan con los atributos y hacen acciones.
  • Se definen dentro de la clase.

5Crear objetos

Los objetos se crean con la palabra clave new.

// Sintaxis
NombreClase nombreObjeto = new NombreClase();

// Ejemplo
Student s1 = new Student();   // s1 es un objeto
Student s2 = new Student();   // s2 es otro objeto

6Acceder a los miembros

Usá el operador punto (.) para acceder a los atributos y métodos de un objeto.

Student s1 = new Student();
s1.name = "Alice";     // acceso a un atributo
s1.age = 20;           // acceso a un atributo
s1.display();          // llamada a un método

7Clase, objeto y memoria

Tip para la entrevista
  • La clase es una plantilla; el objeto es una instancia.
  • Se pueden crear varios objetos a partir de una clase.
  • La memoria de los objetos se reserva en el heap.
Buenas prácticas
  • Diseñá las clases a partir de entidades del mundo real.
  • Mantené los atributos privados y ofrecé métodos públicos (encapsulamiento).
  • Usá nombres con significado para clases, atributos y métodos.

Constructores y palabras clave

1Constructor

  • Un constructor es un método especial que se usa para inicializar objetos.
  • Tiene el mismo nombre que la clase.
  • No tiene tipo de retorno (ni siquiera void).
  • Se llama automáticamente cuando se crea un objeto.
// Sintaxis
class NombreClase {
    NombreClase() {
        // código de inicialización
    }
}
Nota

Los constructores se usan para darles valores iniciales a las propiedades del objeto.

2 · Constructor por defecto

  • Es un constructor sin parámetros.
  • Si no creamos ningún constructor, Java nos da uno por defecto automáticamente.
  • Inicializa el objeto con valores por defecto.
class Student {
    String name;
    int age;

    // Constructor por defecto (lo da Java)
    Student() { }
}

3 · Constructor con parámetros

  • Es un constructor que recibe parámetros.
  • Se usa para inicializar el objeto con valores específicos.
class Student {
    String name;
    int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}

4Palabra clave this

  • this es una variable de referencia que apunta al objeto actual.
  • Se usa para diferenciar las variables de instancia de las variables locales.
class Student {
    String name;
    int age;

    Student(String name, int age) {
        this.name = name;   // apunta a la variable de instancia
        this.age = age;     // apunta a la variable de instancia
    }
}

5Palabra clave static

  • Los miembros static pertenecen a la clase, no a un objeto.
  • Se pueden usar con el nombre de la clase.
  • Se comparten entre todos los objetos.
class Student {
    static int count = 0;   // variable de clase
    String name;

    Student(String name) {
        this.name = name;
        count++;            // es la misma para todos los objetos
    }
}

6Palabra clave final

  • Variable final: su valor no se puede cambiar.
  • Método final: no se puede sobrescribir (override).
  • Clase final: no se puede heredar.
class Student {
    final String COLLEGE = "ABC Institute";   // constante

    final void show() {
        System.out.println("Este método no se puede sobrescribir");
    }
}

Encapsulamiento y herencia

1Encapsulamiento

  • El encapsulamiento es unir los datos (atributos) y los métodos que trabajan con esos datos en una sola unidad: la clase.
  • Restringe el acceso directo a algunas partes del objeto. Es una forma de proteger los datos.
Beneficios
  • Ocultamiento de datos
  • Mayor seguridad
  • Mejor control sobre los datos
  • Mayor flexibilidad

2Getters y setters

  • Se usan para acceder a los atributos private y actualizarlos.
  • El getter devuelve el valor.
  • El setter valida y asigna el valor.
class Employee {
    private String name;

    public String getName() {
        return name;
    }

    public void setName(String name) {
        this.name = name;
    }
}

3Herencia

  • La herencia es el mecanismo por el que una clase adquiere (hereda) las propiedades y los comportamientos de otra clase.
  • Promueve la reutilización del código y establece una relación ES-UN (IS-A).
Relación ES-UN (IS-A)

Si la clase B hereda de la clase A, entonces B ES-UN A. Por ejemplo: Dog ES-UN Animal (un perro es un animal).

4Tipos de herencia

  • Simple: un hijo hereda de un padre.
  • Multinivel: un hijo hereda de un padre, y otro hijo hereda de ese hijo.
  • Jerárquica: varios hijos heredan de un mismo padre.
  • Múltiple: un hijo hereda de varios padres. Java no la permite con clases, pero sí con interfaces.
  • Híbrida: combina dos o más tipos.

5Palabra clave super

  • super es una variable de referencia que apunta al objeto de la clase padre inmediata.
  • Se usa para acceder a los miembros de la clase padre: atributos, métodos y constructores.
class Animal {
    String type = "Animal";
    Animal() { System.out.println("Constructor de Animal"); }
}

class Dog extends Animal {
    String type = "Dog";

    Dog() {
        super();                          // llama al constructor del padre
        System.out.println("Constructor de Dog");
    }

    void show() {
        System.out.println(super.type);   // accede al atributo del padre
    }
}
[revisar] En la lámina decía println(super, type); se corrigió a super.type.

Tip para la entrevista
  • El encapsulamiento protege los datos con private + getters y setters.
  • La herencia modela jerarquías del mundo real con la relación ES-UN.
  • Cuando se pueda, elegí la composición antes que una herencia muy profunda.
Buenas prácticas
  • Declará los atributos private y ofrecé métodos públicos para acceder.
  • Usá nombres con significado para clases y métodos.
  • Usá super() en el constructor hijo para inicializar la parte del padre.
  • Preferí las interfaces antes que la herencia múltiple con clases.

Polimorfismo y abstracción

1Polimorfismo

  • Polimorfismo significa «muchas formas».
  • Permite tratar objetos de distintas clases como objetos de una superclase común.
  • Se logra con la sobrecarga de métodos (en tiempo de compilación) y con la sobrescritura de métodos (en tiempo de ejecución).
Idea clave

Mismo nombre de método, distinto comportamiento. Una interfaz, varias implementaciones.

2 · Polimorfismo en tiempo de compilación

  • Se logra con la sobrecarga de métodos.
  • Mismo nombre de método, distintos parámetros.
  • Lo resuelve el compilador, al compilar.
class Calculator {
    int add(int a, int b) { return a + b; }
    int add(int a, int b, int c) { return a + b + c; }
    double add(double a, double b) { return a + b; }
}

3 · Polimorfismo en tiempo de ejecución

  • Se logra con la sobrescritura de métodos.
  • Mismo nombre y misma firma en la clase padre y en la hija.
  • Lo resuelve la JVM mientras se ejecuta (despacho dinámico).
class Animal {
    void sound() { System.out.println("Sonido de animal"); }
}
class Dog extends Animal {
    @Override
    void sound() { System.out.println("Guau"); }
}
Animal a = new Dog();   // referencia del padre
a.sound();              // Guau (polimorfismo en ejecución)

4 · Clase abstracta

  • Puede tener métodos abstractos y métodos concretos.
  • No se puede instanciar.
  • Se usa para dar una base común y una implementación parcial.
abstract class Shape {
    abstract double area();      // método abstracto
    void display() {             // método concreto
        System.out.println("Esto es una figura");
    }
}

5 · Interfaz

  • Antes de Java 8, solo tenía métodos abstractos.
  • Desde Java 8 puede tener métodos default y static.
  • Es totalmente abstracta = herencia múltiple de tipo.
interface Drawable {
    void draw();                 // método abstracto
    default void info() {        // método default (Java 8+)
        System.out.println("Interfaz Drawable");
    }
}

6Sobrescritura de métodos (overriding)

  • La clase hija da su propia implementación de un método de la clase padre.
  • Tiene que tener el mismo nombre, los mismos parámetros y el mismo tipo de retorno.
  • El nivel de acceso no puede ser más restrictivo.
class Parent {
    void show() { System.out.println("Padre"); }
}
class Child extends Parent {
    @Override
    void show() { System.out.println("Hijo"); }
}

  • La sobrecarga tiene que ver con los parámetros.

Manejo de excepciones

1¿Qué es una excepción?

Una excepción es un evento no deseado o inesperado que interrumpe el flujo normal de un programa.

Beneficios de manejarlas
  • El código es más confiable.
  • Evita que el programa se corte de golpe.
  • Separa la lógica que maneja los errores.
  • Ayuda a depurar mejor.

2Jerarquía de excepciones

3 · try-catch-finally

  • try: tiene el código riesgoso.
  • catch: maneja la excepción.
  • finally: se ejecuta siempre (es opcional).
try {
    int result = 10 / 0;   // código riesgoso
} catch (ArithmeticException e) {
    System.out.println("No se puede dividir por cero");
} finally {
    System.out.println("El bloque finally siempre se ejecuta");
}

4 · throw

  • Se usa para lanzar una excepción a propósito.
  • Podés lanzar cualquier objeto que sea subclase de Throwable.
public void validate(int age) {
    if (age < 18) {
        throw new IllegalArgumentException(
            "La edad tiene que ser 18 o más");
    }
}

5 · throws

  • Se usa en la firma del método para declarar excepciones.
  • Le pasa la responsabilidad a quien llama al método.
public void readFile() throws IOException {
    FileReader fr = new FileReader("file.txt");
}

6Excepción personalizada

Podemos crear nuestras propias excepciones extendiendo la clase Exception.

class InvalidAgeException extends Exception {
    public InvalidAgeException(String msg) {
        super(msg);
    }
}

// Uso
if (age < 0) {
    throw new InvalidAgeException("La edad no puede ser negativa");
}

Tip para la entrevista
  • Preferí siempre las excepciones específicas antes que la Exception general.
  • Usá finally para liberar recursos (base de datos, archivos, streams).
Buenas prácticas
  • Nunca ignores las excepciones.
  • Registrá mensajes de error que se entiendan.
  • No atrapes Exception salvo que haga falta.
  • Usá excepciones personalizadas para representar las reglas del negocio.

Conceptos avanzados de Java

Estos conceptos se preguntan seguido en las entrevistas y se usan en aplicaciones reales.

1 · API de reflexión (Reflection)

La reflexión permite inspeccionar y modificar clases, métodos y atributos mientras el programa se ejecuta.

Class<?> clazz = Class.forName("Student");
Object obj = clazz.getDeclaredConstructor().newInstance();
Method m = clazz.getMethod("setName", String.class);
m.invoke(obj, "Mahesh");
Field f = clazz.getDeclaredField("age");
f.setAccessible(true);
f.setInt(obj, 25);

Usos: frameworks, inyección de dependencias y carga dinámica de clases.

2 · Anotaciones

Las anotaciones le dan metadatos al compilador o al entorno de ejecución. No cambian la lógica del programa.

@Override
public String toString() {
    return "Student";
}

@Deprecated
public void oldMethod() {
    // hace algo
}

Anotaciones que ya trae Java: @Override, @Deprecated, @SuppressWarnings, @FunctionalInterface, @Retention, @Target.

3 · Clase inmutable

Una clase inmutable no se puede cambiar una vez que se creó el objeto. Todos los atributos son final y no hay setters.

final class Person {
    private final String name;
    private final int age;
    public Person(String name, int age) {
        this.name = name; this.age = age;
    }
    public String getName() { return name; }
    public int getAge() { return age; }
}

Ventajas: es segura para hilos (thread-safe), es segura, se puede usar como clave de un Map y es fácil de guardar en caché.

4 · Patrón Singleton

Asegura que exista una sola instancia de una clase y da un punto de acceso global.

class Singleton {
    private static Singleton instance;
    private Singleton() { }
    public static Singleton getInstance() {
        if (instance == null)
            instance = new Singleton();
        return instance;
    }
}

Tipos: inicialización ansiosa (eager), inicialización perezosa (lazy), doble verificación con bloqueo (double-checked locking) y Singleton con enum. La mejor forma: usar un Singleton con enum.

5Clases internas

Una clase interna es una clase definida dentro de otra clase.

TipoCaracterísticas
Clase interna no staticTiene acceso a los miembros de la clase externa.
Clase anidada staticSe comporta como una clase normal. No puede acceder a los miembros no static de la clase externa.
Clase interna localSe define dentro de un método. Solo se puede usar dentro de ese método.
Clase interna anónimaNo tiene nombre y se usa una sola vez. Es común con interfaces o clases abstractas.

6Enums

Un enum es un tipo de dato especial que representa un grupo de constantes (inmutables).

enum Day {
    MONDAY, TUESDAY, WEDNESDAY,
    THURSDAY, FRIDAY, SATURDAY, SUNDAY;
}

Day d = Day.MONDAY;
System.out.println(d);   // MONDAY
  • Es seguro en tipos (type-safe).
  • Extiende implícitamente java.lang.Enum.
  • Puede tener atributos, constructores y métodos.
  • Se usa en sentencias switch.
Puntos clave
  • Usá la reflexión para operaciones dinámicas.
  • Usá anotaciones para configuración y metadatos.
  • Los objetos inmutables son seguros y thread-safe.
  • El Singleton controla la creación de objetos.
  • Las clases internas mejoran la organización del código.
  • Los enums son mejores que las constantes int.
Preguntas de entrevista
  • ¿Qué diferencia hay entre una clase anidada static y una clase interna?
  • ¿Cómo se rompe un Singleton usando reflexión? (Usá enum para evitarlo).
  • ¿Por qué la clase String es inmutable?
  • ¿Cuándo conviene un enum y cuándo constantes de clase?
Buenas prácticas
  • Preferí la composición antes que anidar en profundidad.
  • Evitá la reflexión salvo que haga falta.
  • Hacé las clases inmutables siempre que puedas.
  • Usá el Singleton con enum para que sea seguro con hilos.
  • Documentá con claridad las anotaciones personalizadas.
Errores comunes
  • Olvidarse de cerrar los recursos.
  • Usar Statement con datos que escribe el usuario (inyección SQL).
  • No manejar las excepciones de SQL.

  • Cuando no necesitás acceder por índice.

El framework Map en Java

La interfaz Map de java.util guarda los datos en pares clave-valor. Cada clave tiene que ser única y corresponde a exactamente un valor.

1Implementaciones de Map

HashMap

  • La implementación más común.
  • Sin orden; permite una clave null y valores null.
  • No está sincronizada.

LinkedHashMap

  • Mantiene el orden de inserción con una lista doblemente enlazada.
  • Permite clave null y valores null.
  • Es un poco más lenta que HashMap.

TreeMap

  • Guarda las claves ordenadas (orden natural).
  • No permite clave null.
  • Es más lenta que HashMap.

Hashtable

  • Clase heredada de versiones viejas (legacy, Java 1.0).
  • Sincronizada y segura para hilos.
  • No permite claves ni valores null.

2Cómo funciona HashMap por dentro

  • HashMap usa una tabla hash (un array de «cubetas», en inglés buckets).
  • El hashCode() de la clave se usa para encontrar el índice.
  • Las colisiones se manejan con una lista enlazada (o con un árbol, desde Java 8).

Fundamentos de JDBC

JDBC (Java Database Connectivity, conectividad de Java con bases de datos) es una API que permite que las aplicaciones Java se conecten con bases de datos y trabajen con ellas.

1Arquitectura de JDBC

2 · DriverManager

  • Se usa para establecer una conexión.
  • Carga el driver adecuado y crea la conexión.
Connection conn = DriverManager.getConnection(

    "root", "password");

3 · Connection

  • La interfaz Connection representa una sesión con la base de datos.
  • Se crea con DriverManager.
  • Se usa para crear Statement, PreparedStatement o CallableStatement.
Connection conn = DriverManager.getConnection(
    "jdbc:mysql://localhost:3306/qa_db", "root", "password");
// No te olvides de cerrar la conexión

4 · Statement

  • Se usa para ejecutar consultas SQL simples.
  • No es seguro frente a la inyección SQL.
  • Sirve para consultas SQL estáticas.
Statement stmt = conn.createStatement();
String sql = "SELECT * FROM users";
ResultSet rs = stmt.executeQuery(sql);

5 · PreparedStatement

  • Son sentencias SQL precompiladas.
  • Permiten consultas con parámetros.
  • Protegen de la inyección SQL y mejoran el rendimiento.
PreparedStatement ps = conn.prepareStatement(
    "SELECT * FROM users WHERE id = ?");
ps.setInt(1, 101);
ResultSet rs = ps.executeQuery();

6ResultSet

  • ResultSet representa el resultado de una consulta.
  • Tiene un cursor para recorrer las filas.
while (rs.next()) {
    int id = rs.getInt("id");
    String name = rs.getString("name");
    System.out.println(id + " - " + name);
}

7Las cuatro operaciones CRUD

Puntos clave: los pasos de JDBC
  1. Cargar el driver (desde JDBC 4 es automático).
  2. Obtener una Connection.
  3. Crear un Statement o un PreparedStatement.
  4. Ejecutar la consulta SQL.
  5. Procesar el ResultSet.
  6. Cerrar los recursos.
Tip para la entrevista
  • ¿Qué es JDBC? → Una API para conectar Java con una base de datos.
  • ¿Qué diferencia hay entre Statement y PreparedStatement?
  • ¿Por qué hay que cerrar Connection, Statement y ResultSet?
Buenas prácticas
  • Usá PreparedStatement por seguridad y rendimiento.
  • Cerrá siempre los recursos (try-with-resources): Connection, Statement y ResultSet.
  • Manejá las excepciones con mensajes que se entiendan.
Errores comunes
  • Olvidarse de cerrar los recursos.
  • Usar Statement con datos que escribe el usuario (inyección SQL).
  • No manejar las SQLException.

Archivos y serialización

Java tiene clases para trabajar con archivos y para guardar objetos de forma permanente usando la serialización.

1Clases para manejar archivos

File

  • Representa la ruta de un archivo o de una carpeta.
  • Tiene métodos para crear, borrar, verificar si existe, etc.
File f = new File("test.txt");
f.createNewFile();
f.exists();
f.delete();

FileReader

  • Lee datos de tipo carácter de un archivo.
  • Se usa para leer caracteres de forma simple.
FileReader fr = new FileReader("a.txt");
int ch;
while ((ch = fr.read()) != -1)
    System.out.print((char) ch);
fr.close();

FileWriter

  • Escribe datos de tipo carácter en un archivo.
  • Si el archivo no existe, lo crea.
FileWriter fw = new FileWriter("a.txt");
fw.write("Hola Java");
fw.flush();
fw.close();

BufferedReader

  • Lee texto de forma eficiente, línea por línea.
  • Usa un búfer interno para rendir mejor.
BufferedReader br = new BufferedReader(
    new FileReader("a.txt"));
String line;
while ((line = br.readLine()) != null)
    System.out.println(line);
br.close();

BufferedWriter

  • Escribe texto de forma eficiente, línea por línea.
  • Usa un búfer interno para rendir mejor.
BufferedWriter bw = new BufferedWriter(
    new FileWriter("a.txt"));
bw.write("Hola Java");
bw.newLine();
bw.close();
[revisar] En la lámina decía new BufferedReader(; se corrigió a BufferedWriter.

2Serialización y deserialización

La serialización es convertir el estado de un objeto en un flujo de bytes (byte stream), para poder guardarlo en un archivo o mandarlo por la red. La deserialización es el proceso inverso: convierte el flujo de bytes otra vez en un objeto.

Pasos para serializar

  1. El objeto tiene que implementar la interfaz Serializable.
  2. Usá ObjectOutputStream para escribir el objeto en el archivo.
class Student implements Serializable {
    String name; int age;
    Student(String n, int a) { name = n; age = a; }
}

Student s = new Student("Mahesh", 25);
FileOutputStream fos = new FileOutputStream("student.ser");
ObjectOutputStream oos = new ObjectOutputStream(fos);
oos.writeObject(s);   // serialización
oos.close(); fos.close();

Pasos para deserializar

  1. Usá ObjectInputStream para leer el objeto del archivo.
  2. Convertí (cast) el objeto a su clase original.
FileInputStream fis = new FileInputStream("student.ser");
ObjectInputStream ois = new ObjectInputStream(fis);
Student s2 = (Student) ois.readObject();   // deserialización
System.out.println(s2.name + " " + s2.age);
ois.close(); fis.close();
Puntos clave
  • La clase File se usa para operaciones con archivos y carpetas.
  • Usá las clases con búfer (BufferedReader/BufferedWriter) para rendir mejor.
  • La serialización sirve para guardar (persistir) el estado de un objeto.
  • La deserialización vuelve a armar el objeto a partir del estado guardado.
  • Las clases que se serializan tienen que implementar Serializable.
  • Los atributos transient y static no se serializan.
Tip para la entrevista
  • ¿Qué diferencia hay entre File y Path?
  • ¿Cuándo usar BufferedReader en vez de FileReader?
  • ¿Para qué se usa la serialización?
  • ¿Qué pasa si cambia el serialVersionUID?
  • ¿Qué diferencia hay entre Serializable y Externalizable?
Buenas prácticas
  • Cerrá siempre los streams en un bloque finally o usá try-with-resources.
  • Evitá serializar cuando no haga falta.
  • Usá streams con búfer para los archivos grandes.
  • Validá las rutas de los archivos y manejá las excepciones.
Recordá
  • Serialización = objeto → flujo de bytes (guardar).
  • Deserialización = flujo de bytes → objeto (cargar).
Excepciones comunes
  • FileNotFoundException: no se encontró el archivo.
  • IOException: falla general de entrada y salida.
  • ClassNotFoundException: no se encontró la clase al deserializar.

Para cerrar

En pocas palabras

  1. Escribís el código en un archivo .java, javac lo compila a bytecode (.class) y la JVM lo ejecuta en cualquier sistema operativo: escribilo una vez, ejecutalo en cualquier lado.
  2. Cada variable tiene un tipo. Los primitivos (int, double, boolean…) guardan el valor; los no primitivos (String, arrays, objetos) guardan una referencia.
  3. Con condiciones, bucles y métodos controlás el flujo del programa y lo dividís en partes que podés reutilizar.
  4. La programación orientada a objetos se apoya en clases y objetos, encapsulamiento, herencia, polimorfismo y abstracción.
  5. Para programas reales vas a usar excepciones para los errores, colecciones y Map para los datos, JDBC para las bases de datos y la serialización para guardar objetos.

Glosario

Bytecode
Código intermedio que genera javac en un archivo .class y que ejecuta la JVM.
Casting (conversión de tipos)
Convertir un valor de un tipo de dato a otro: solo (ensanchamiento) o a mano (estrechamiento).
Clase
Plano o plantilla que define los atributos y los métodos de los objetos.
Colección
Objeto que agrupa varios elementos, como una List, un Set o una Queue.
Constructor
Método especial, con el mismo nombre que la clase, que inicializa el objeto cuando se crea.
Encapsulamiento
Unir datos y métodos en una clase y restringir el acceso directo a los datos.
Excepción
Evento inesperado que interrumpe el flujo normal del programa.
Heap
Zona de la memoria donde se guardan los objetos que se crean con new.
Herencia
Mecanismo por el que una clase adquiere los atributos y métodos de otra (relación ES-UN).
Interfaz
Tipo abstracto que define un contrato: los métodos que una clase se compromete a tener.
Inyección SQL
Ataque que mete código SQL a través de los datos que escribe el usuario. Se evita con PreparedStatement.
JDBC
API para conectar programas Java con bases de datos.
JDK
Kit de desarrollo de Java: el JRE más herramientas como javac.
JIT
Compilador «justo a tiempo» de la JVM: pasa el bytecode a código máquina mientras el programa se ejecuta.
JRE
Entorno de ejecución de Java: la JVM más las bibliotecas.
JVM
Máquina virtual de Java. Ejecuta el bytecode.
Literal
Valor escrito directamente en el código, como 25, 'A' o "Hola".
Map
Estructura que guarda pares clave-valor, con claves que no se repiten.
Método
Bloque de código que hace una tarea específica.
Objeto
Instancia de una clase, con sus propios datos.
Paquete
Espacio de nombres que agrupa clases e interfaces relacionadas.
Polimorfismo
Capacidad de un mismo método de comportarse distinto según el objeto que lo ejecuta.
Recursión
Técnica en la que un método se llama a sí mismo.
Serialización
Convertir un objeto en un flujo de bytes para guardarlo o mandarlo por la red.
Sobrecarga (overloading)
Varios métodos con el mismo nombre y distintos parámetros.
Sobrescritura (overriding)
Una clase hija vuelve a definir un método de la clase padre.
String Pool
Zona de la memoria donde Java guarda los literales String para reutilizarlos.
